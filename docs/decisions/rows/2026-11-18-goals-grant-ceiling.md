needed-by: Agents, built 2026-11-18 (lane AG; ADR 0013 sections 1 and 5; the manager asked for it before G1b, after A-core found that the built-in goals agent holds no rows; host only)
decision: The `goals` agent's ceiling is per goal: set only by the person's yes to `goal_set` through `kai`, holding only the rows that goal's scope names, never a send or an install row, and ending with the goal
---
A built-in agent other than `kai` holds no grants of its own, so `goals` was refused at the door for every row (A-core, on #1056). `agentid::Roster::grant_goal(by, mark, goal, scope, rows)` sets a goal's ceiling. `by` must be `kai`, the shell running the approved `goal_set`, and `mark` must be the person's, from the key that answered `goal_set`'s one ask. It takes the mark, not the `Answered`, because the answer is spent on running `goal_set` itself. Each scope entry, a row or `<group>_*`, is resolved against the registry. An entry that is, or covers, a row that sends past the machine (`open_world` and not read-only) or installs, removes or switches code or a model (`pkg_install`, `pkg_remove`, `app_build`, `app_install`, `model_fetch`, `model_use`) refuses the whole grant, named, so `pkg_*` cannot reach `pkg_install`. A read past the machine, such as `net_fetch`, is no send. A never-tier row, an unknown row or an empty scope is refused too. At most 16 goals hold a ceiling at once. `Roster::admit_for_goal(caller, goal, row)` admits only the `goals` agent, only for a row its goal's ceiling holds, and never a send or install row even if a ceiling named one. The admission carries the goal, so a call that waited is checked again against it. `Roster::revoke_goal` ends the ceiling with the goal (done, failed, cancelled, forgotten), and a waiting call is then refused. The tiers still decide below the ceiling: the door's ask for a row with no undo, or for a content-steered call, still reaches the person's card. `goals` never gets the person's consent words, since `Admission::consent_words` gives them to `kai` only.
