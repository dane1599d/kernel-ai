decision: A goal's ceiling also never covers a code switch (`component_revert`, `tune`, `tune_undo`) or a change to what apps may reach (`grant_revoke`, `grant_restore`), and a test walks every row of the registry so a new one cannot slip past unsorted
---
The audit found `component_revert` (a live component swapped to an earlier version, a local change at the run tier) outside `INSTALL_ROWS`. So a goal scope of `component_revert` or `component_*` would have been granted, against the rule that a ceiling never covers a row that switches code; `tune` (a kernel scheduler trial) looked the same. Both join `INSTALL_ROWS`, and so does `tune_undo`, which swaps back the policy a trial kept. Walking the registry also found `grant_revoke` and `grant_restore`. They are no install, but they change what apps may reach, and a goal that could restore a grant could widen itself. So they are `PERMISSION_ROWS`, refused by name as `GrantRefused::Permissions` and never admitted. The new test sorts every row of `agentabi::ROWS` into a read, a send by its facts, an install, a permission change, or a reviewed local change listed in the test (the scheduler policy, process and service starts and stops, reboot, the file writes, the window rows, appearance). A row that is none of these fails the test until someone sorts it. Every listed name must be a row of the registry, so a rename is seen. The tiers still decide below the ceiling, so a reviewed change with no undo still asks the person.
