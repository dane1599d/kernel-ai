needed-by: Agents, built 2026-11-18 (lane AG; ADR 0013 section 1; the manager's agent-identity audit of llm, before any agent's plan line routes to llm; stacked on #1010)
decision: llm serves the person's commands only to `kai` and to badge 0's services; an agent's badge may send `agent-*` alone, and an agent's act is decoded against the pack's own grammar, never the person's apps
---
The audit found two latent gaps, latent because no agent program had a route to llm yet. First, llm gated only `agent-*` by badge. Every other command was served to any badge: `act` with the person's conversation, `remember`, `new`, the app rounds (`app-start`, `app-take`, `app-stop`), `explain`, `query`, `tune`, `warm-lang`, plain `ask` and `script`, `health`. So an agent could have read the person's history, planted a turn in it, wiped it, or stopped their app round. Now `agentsched::jobs::may_serve(badge, text)` holds them to `kai` and to badge 0, the services that call llm with no agent's badge (`updated`, the Monitor window). Any other badge gets `err agents use agent-start`, before llm reads the request. The app round's own loop gates the same way: it receives with `RECV_H`, refuses a stranger's command, and answers an `agent-*` that comes during a round with busy. Second, an agent's `act` job fed its request's `apps` into the shared app table and grammar, so an agent could change which app rows the person's next call was decoded with. Now an agent's call is decoded against `base_grammar`, the pack's rows alone, built once at load, and its `apps` are never read. The person's `act` still brings the installed apps' rows. A test holds `may_serve` to the person's commands for every agent badge. llm itself is not host-tested, so the refusal before dispatch, and with it the person's history left unchanged, is held by the gate's placement ahead of every handler, and by the `agent-job` boot case.
