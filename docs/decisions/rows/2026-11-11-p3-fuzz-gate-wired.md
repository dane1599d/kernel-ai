decision: P3's four fuzz targets are in fuzz/ and run weekly by fuzz.yml on a GitHub runner; the gate closes on their first clean run
---
The gate the 2026-11-09 row left open asks for a fuzz target for every new P3 parser. `fuzz/` now has four: `surfabi_stream` (`surfabi`'s message decoder, as `desktop` serves a client's bytes), `header_page` (the header page, latched and its ring taken), `tree_records` (the accessibility tree's records, decoded and applied) and `kai_theme` (`look`'s `kai-theme 1`, which must check and read back the same once parsed). Their bodies are `fuzz/surfabi_harness.rs` and `fuzz/look_harness.rs`, which `surfabi/tests/hostile.rs` and `look/tests/hostile.rs` now include. So the hostile tests and libFuzzer run the same code, and those tests' samples are the targets' seeds, written into `fuzz/corpus` by an ignored test the workflow runs first. `fuzz.yml` was on demand only; it now also runs every target, kainet's six included, for 300 s each on Mondays at 03:17 UTC, and on demand as before. The gate is met once a run of the four new targets on a GitHub runner finds no crash; the pull request that adds them records that run.
