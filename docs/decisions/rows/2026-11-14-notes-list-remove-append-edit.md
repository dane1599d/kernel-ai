needed-by: the first-time-user audit, item 15 (Notes cannot list, delete or edit), built 2026-11-14 (AP-1; A-core reviews the model-facing rows, fluency and actbench before merge)
decision: Notes gets four actions, `list`, `remove`, `append` and `edit`, each undone by a snapshot, and a Delete button; `find` stays as it is.
---
"Show my notes", "delete the ideas note" and "add milk to my shopping note" all failed because Notes could only add, count, find ids, get and say its version, and the window had no way to delete. `app:notes/actions@1.0.0` (`components/notes/wit/notes.wit`) grows in place, as an app's interface may (only the `kai:` packages are frozen, ADR 0003): `list` returns one line `id: first line` for each note, the first 100, each line cut at 60 characters, a reply that fits one message and is read-only; `remove(id)` takes a note away (declared destructive, so a standing instruction cannot run it unasked, and undone by a snapshot like `add`); `append(id, text)` adds a line at the end of a note; `edit(id, text)` replaces its whole text. The three that change answer with a line (`Removed note 2.`, `Added to note 1.`, `Changed note 3.`), as the Editor's actions do, so the model's second round has something to say. A note holds at most 2000 bytes and the state still at most `MAX_STATE`: a note that would not fit is refused (`a note holds at most 2000 bytes`, `notes are full`) and left as it was. An id that is not there, or nothing to add, is an error naming it, not a trap. Ids are not given again after a removal. The window's build writes each change to its storage as `add` does (`stored::save` already took a removed note's key away), and its editor closes if the note it had open is removed. In the window the Delete button shows only while a note is open, removes it and goes back to "No note open"; a person's click is a window event, not an action, so it has no snapshot to undo (the same as the editing it sits beside) and is not bound to a row. `comp_notes::Actions` gets the four as default methods (nothing for `list`, a refusal for the rest), so the older versions that ship for the live-swap and rollback tests, `notes-v1` and `notes-bad`, are untouched and export the new functions with those answers. What this does not do, on purpose: `find` still returns ids only. The audit asked it to return first lines, but changing its result type inside `@1.0.0` breaks the version scenarios that compare its answers across a swap (`livecore`'s `scenario.rs`) and the older versions; `list` is where a first line comes from, and `find` then `get` or `list` is what the model does. Model input changes: nine rows in the apps turn instead of five, and the `apps` arm of actbench has four new tasks (`show me all my notes`, `add eggs to note 1`, `delete note 2`, `change note 3 to buy bread`), reported, not gated. The fluency gate (`fluency-model.yml`, started by hand) and the actbench `apps` arm are the checks the audit asks for before merge: they need A-core's item 3 (the apps turn built from installed packages, not from windows that are open) to show the rows to the model on a fresh boot, so the runs follow that. Not run here.
