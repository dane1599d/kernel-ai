needed-by: Agents, built 2026-11-11 (lane E; ADR 0013 section 2 on the host before the v0.1 tag; stacked on `Engine::continue_reply`)
decision: The scheduler's preemption is exact with the real engine: an integration test runs `agentsched` over `infer` on the fixture model, with snapshots in a pool, and every answer equals the one the agent gets alone
---
`agentsched/tests/engine.rs` is the host half of the `llm` wiring that comes after the tag. A rig carries out the scheduler's decisions on an `infer::Engine` with two slots (or one): `Move` from a slot to the RAM pool is `snapshot_slot`, from the pool to a slot is `restore_snapshot` into whichever slot is free (the pool's keys are bound to the agent's request through `spill_pack_id` and to no slot), a prefill quantum is `reply` stopped after the block that ran, the first decode token is `reply` for one token and each later one is `continue_reply` of one token (the scheduler's quantum), and a request the model ends early is `finish`ed. Every answer is compared token for token with the answer made when the agent has the model to itself.

Three cases, on every tier: the person's request arriving while two background agents are mid-sentence on two slots (an agent's state leaves its slot for the pool and comes back; the person's request finishes before either agent; everything is exact); the person's request arriving while an agent is only part way through its prompt, on one slot (the partly filled cache goes to the pool and comes back, and the agent's prompt goes on from it); and two agents sharing one slot, trading state through the pool (every state that left came back). All exact.

What the rig teaches the wiring, since the first run failed on it: a request that finishes frees its slot at once, and the scheduler counts on that (`Move` into a slot after a request ends finds one free); a decode quantum cannot start from the logits the last quantum left, since they are the engine's and shared, so the first token is a `reply` that re-runs the prompt's last token and each later one a `continue_reply` that runs the pending token; and correctness does not depend on the scheduler's counts of prompt tokens agreeing with the engine's (a cached prefix makes the engine's smaller), because a short prefill quantum only does less and the first decode `reply` does any prefill that is left. Grammar-shaped answers (`act`, `script`) are not carried on by `continue_reply` and are not in this rig.
