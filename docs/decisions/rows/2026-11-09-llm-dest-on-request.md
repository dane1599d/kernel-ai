decision: Only a plan line that says `netdest=llm` starts with a handle to the LLM server's destination; `caps=net` alone gives no handle
---
#756 made HTTP to the LLM need a handle to `netdest::LLM` itself, not any `NetDest`. But every process with `caps=net` still started with that handle, so any NET holder could reach the LLM unless it closed the handle itself, as T's `fetch` does. Now the handle goes only to a line that asks for it with `netdest=llm`, which is bound to its line's program like every `netdest=`. Today that is the `llm` service's line (`kernel/src/llm.rs`). NET stays the kind ceiling for `NetDest` handles, so a NET holder may still take a moved-in destination. The `net-dest` boot case's `netdest-g` step proves the rule: `netcheck`, started with NET and another `NetDest` but no `netdest=llm`, holds no LLM handle and its HTTP is refused. The plan grammar gains one value of `netdest=`, and no call or number moves, so the ABI does not move. ADR 0001's bit-to-handle table records the change.

Follow-up after the manager's review of #779:
- `netdest=llm` is now refused on any line but `llm` running `llm` with `net` in its ceiling, and `spawn_in` gives the handle only within the ceiling. So NET bounds the LLM's handle as it bounds a moved-in `NetDest` (`handle::take_for` checks the receiver's ceiling). A plan line's own `netdest=` record is different: the line bounds it, whatever its caps (`pkg` and `updated` hold one with no `net`, #829).
- `net-dest`'s `netdest-l` step shows the grant directly: through `spawn_in`, the process starts with the LLM's handle, exactly CONNECT, with NET, and with no `NetDest` without it.
- A `test=update` boot passes only the `updated.<key>=` words `updated` reads (`restart`, `window`, `heads_up_s`) onto its line, so a command line cannot add `netdest=` there.
- The rule covers `call::HTTP`, not raw TCP. A record `NetDest` whose hosts or addresses cover the LLM server's address and port still connects there with `NET_CONNECT` (`kernel/src/net/dest.rs`; `special()` does not cover private ranges such as 10.0.2.2). Closing that is for `special()` or the LLM server's address, not this row.
