decision: Only a plan line that says `netdest=llm` starts with a handle to the LLM server's destination; `caps=net` alone gives no handle
---
#756 made HTTP to the LLM need a handle to `netdest::LLM` itself, not any `NetDest`. But every process with `caps=net` still started with that handle, so any NET holder could reach the LLM unless it closed the handle itself, as T's `fetch` does. Now the handle goes only to a line that asks for it with `netdest=llm`, which is bound to its line's program like every `netdest=`. Today that is the `llm` service's line (`kernel/src/llm.rs`). NET stays the kind ceiling for `NetDest` handles, so a NET holder may still take a moved-in destination. The `net-dest` boot case's `netdest-g` step proves the rule: `netcheck`, started with NET and another `NetDest` but no `netdest=llm`, holds no LLM handle and its HTTP is refused. The plan grammar gains one value of `netdest=`, and no call or number moves, so the ABI does not move. ADR 0001's bit-to-handle table records the change.
