needed-by: Agents, built 2026-11-09 (lane E; the manager asked for ADR 0013's pre-tag reservations as one small refusing change; to be cherry-picked to release/v0.1 together with its follow-up)
decision: Before the v0.1 tag, ADR 0013 takes three row-group names, the package kind `agent` and two volume names, by refusing them
---
Each is a refusal, not a feature, so the tag can carry them and the agents track can build on them after it (ADR 0013, "Phases that depend on it").

- **Row groups.** `agent`, `goal` and `search` join `agentabi::RESERVED_GROUPS` (`memory` is there already, as the `memory` row's group). No package may take one of these names, so a package `search` exporting `files` can never make `search_files`, and the rows the track adds later (`agent_*`, `memory_*`, `search_files`, `goal_*`) cannot collide with a package's actions. The built-in agents' own names (`kai`, `goals`, `index`, `maint`) are not groups. `kaipkg`'s `valid_name` asks this list, and it runs wherever a package name is made, not only for installed packages: a package header (`kaipkg/src/header.rs`), the catalogue, a generation, a locally built app (`local.rs`) and ccserve's `app_build`. So a locally built app named `agent`, `goal` or `search` is refused now, as the other reserved names already are; ccserve's "is an OS row group" goes to the model as a repair line, and the prompt, the row pack and the State line are untouched.
- **Package kind.** `kind agent` is refused by name in `kaipkg` ("reserved in format 1 (ADR 0013)"), as `kind tool` is, so v0.1's `pkg` refuses an agent package cleanly rather than as an unknown kind. A test pins both named refusals.
- **Volumes.** `kaifs::vol::RESERVED_VOLUMES` names `memory` and `index`: no volume is made with either. `mkfs` makes neither, and `Fs::build`, the one place volumes are made, asks `check_new_volume` for every name before it writes and refuses with `Unsupported("a volume named for ADR 0013's later volumes")`. **Reading is not refused**: a volume entry that names one loads like any other, and whether an older slot can mount a disk a later version wrote is for the format's compat bits to say (ADR 0004), so a v0.1 slot is not ruled out of mounting such a disk ahead of that decision (a rollback). Adding the volumes is a format change, made when they land.

No WIT and no `actlog` change. Nothing in the v0.1 catalogue is named like any of these, and no disk v0.1 makes or reads is refused.
