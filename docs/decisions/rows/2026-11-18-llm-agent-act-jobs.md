needed-by: Agents, built 2026-11-18 (lane AG; ADR 0013 sections 1-2, row F3 of docs/plans/agents-os.md, slice 2b; stacked on #1008)
decision: An agent's `act` job is decoded with an empty conversation of its own, never the person's, locally and on a server; after one, the person's act prefix and history are computed again before their next request
---
Slice 2a refused agents' `act` requests because llm's `act` reads the person's conversation memory (P1 plan section 4) and takes the act slot. Now `Local::act_until(request, Whose, stop)` decodes the call with `Whose::Person`'s history, as before, or with `Whose::Agent`'s, which is an empty `History` made for that call. The person's turns are never in an agent's prompt, and an agent's call adds nothing to them (`routed` only reads history; `remember` is the shell's alone). On a server backend the agent's call is sent with an empty history too. The call's decode stops on the same 50 ms poll as the other jobs, and an interrupted call starts again from its prompt. Since the act slot then holds a prefix with no history, `stale` is set and the idle turn re-warms the person's act prefix with their history before the next agent job. The script slot is re-warmed as for other jobs, since a routed call may use it. Foreground timing changes only by that re-warm, which runs in idle time. The person's own `act` still goes through `Local::act` unchanged. An agent's request still carries its own `apps` rows, which may rebuild the grammar; the person's next request rebuilds it from theirs.
