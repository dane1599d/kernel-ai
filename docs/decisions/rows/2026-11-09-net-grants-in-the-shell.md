decision: Per-app network grants live in the shell's `/system/state/netgrants` as `kai-grants 1` host lines, asked on the terminal's card, listed and revoked on Settings' Network page, each with `undo`
---
The shell owns the grants until `powerbox` takes `/system/grants`, as it owns the standing rules. The file is the one copy: each decision reads it, each change writes it before the change is told, and a file out of shape fails closed (no host is granted or asked, and nothing overwrites it). At start the `session` grants are dropped. An app's first connection to a host inside its package's `NetDest` waits as a card the kernel's terminal takes (`CARD_READY`, then `TAKE_CARD`), as Kai's install card does, with the highlight on Deny since no typed line asked for it. Its question shows the call `net_connect("<app>", "<host>")` word for word, which the Allow's `ONCE` names. "Allow" keeps a `session` grant; "Always allow on <host>" a `persistent` one; there is no "every host" choice. A grant is for one host (`match:exact`), never a suffix, and the app's `NetDest` is exactly its granted hosts that the package still names, with no literal address. Settings' new last tab, Network, lists each grant (`net`) with Revoke (`net-revoke <n>`), logged as the user's click. `undo` of an Allow takes the grant back, and `undo` of a revoke puts it back under its own id. Revoked grants are kept in memory for that undo, so it works until the shell restarts, as a profile switch's does. Part 2 wires comphost: an app's `kai:net/http` request asks the shell (`granted <netdest>`, `asked` or `refused <why>`), narrows the app's ceiling handle to the answer, and passes it to `fetch` (task 12, lane N-t), where the boot case `net-grant` runs end to end. Redirects (the manager's question on #750): `fetch` follows a redirect only to a host the handle it was given already allows. A redirect to any other host is not followed but handed back to comphost as the new URL, and comphost treats it as a new request: it asks the shell about that host (a grant, a card or a refusal), narrows a handle to it and calls `fetch` again, counting the hop against task 5's limit of 5. So GitHub's release-asset hop or a CDN host such as `cdn-lfs.hf.co` asks once, by its own name, and is never covered by a suffix the person did not see. The other way, a grant covering named redirect suffixes, was not taken: it would let one Allow reach hosts the card never named.
