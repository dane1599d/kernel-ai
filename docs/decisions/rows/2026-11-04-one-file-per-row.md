decision: A new decision is one file under docs/decisions/rows/, not a row appended to docs/decisions.md.
---
Nearly every open pull request showed CONFLICTING on GitHub because each appended a row to the end of the one table in `docs/decisions.md`. GitHub's mergeability check ignores the `merge=union` attribute that makes our own batch merges clean, so it ran no CI on a conflicting pull request and the lanes kept merging main in. A row is now `docs/decisions/rows/<date>-<slug>.md` (`cargo xtask decisions new <slug>`), so two pull requests never touch the same file. The existing rows stay in `decisions.md`, and its `merge=union` stays for the pull requests already open. `cargo xtask decisions check` runs in the lint job: it refuses a malformed row file, a `docs/decisions/ROWS.md` row that no file has, and (when `docs/decisions/LEGACY` says `mode strict`) a `decisions.md` that has grown. `ROWS.md` is the table of all the row files and is written by `cargo xtask decisions write` in the batch, never by a pull request, or it would be the new place everything conflicts. Open: who runs `write` (the batcher), and when to flip `LEGACY` to `strict`.
