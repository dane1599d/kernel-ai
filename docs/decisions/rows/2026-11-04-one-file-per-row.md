decision: A new decision is one file under docs/decisions/rows/, not a row appended to docs/decisions.md.
---
Nearly every open pull request showed CONFLICTING on GitHub because each appended a row to the end of the one table in `docs/decisions.md`. GitHub's mergeability check ignores the `merge=union` attribute that makes our own batch merges clean, so it ran no CI on a conflicting pull request and the lanes kept merging main in. A row is now `docs/decisions/rows/<date>-<slug>.md` (`cargo xtask decisions new <slug>`), so two pull requests never touch the same file. The existing rows stay in `decisions.md`, and its `merge=union` stays for the pull requests already open. Nothing generated is committed (a shared generated table would bring the conflicts back): `cargo xtask decisions` prints the table of the row files on demand. The lint job runs `cargo xtask decisions check`, which refuses a malformed row file and, on a pull request, warns when `decisions.md` gained a row compared with its base. Open: when to add `--deny-new-rows` so that warning fails.
