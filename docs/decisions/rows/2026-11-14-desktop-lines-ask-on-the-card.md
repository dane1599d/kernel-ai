decision: A line that asks first, typed in the AI panel or the Terminal window, waits for the desktop's trusted card, and the person answers Run or Don't there
---
In the founder's first VirtualBox test, nothing on the desktop could approve an ask-first action. The panel said "ask in the terminal", the Terminal window said "ask in the console" (Ctrl+Alt+F12), and a note could not be made without the kernel's console. Now such a line's proposal, when it is an Allow / Deny menu (one call, the act model's rows), waits as a card, as an app's network ask does (`shellcore::deskask`). The kernel's terminal takes it (`TAKE_CARD`) when `desktop` shows and no other ask is up, and posts it on `desktop`'s trusted ask card. Code draws the call and the question, the person answers there, and an Allow mints the `ONCE` for the call as shown (ADR 0005 section 7). The panel and the window only put the question in line and never answer it, and neither does a typed "yes". No typed line at the trusted terminal asked for the card, so its highlight starts on Deny. At most four wait; one older than a question's two minutes lapses ("expired" in the log). What the answer came to shows on the panel. A Rhai script the model wrote still asks a y/n question that only the console shows, because the card shows one call and never a script, so that line is refused with that reason. A follow-up is a card that shows a script whole.
