decision: A line that asks first, typed in the AI panel or the Terminal window, waits for the desktop's trusted card, and the person answers Run or Don't there
---
In the founder's first VirtualBox test, nothing on the desktop could approve an ask-first action. The panel said "ask in the terminal", the Terminal window said "ask in the console" (Ctrl+Alt+F12), and a note could not be made without the kernel's console. Now such a line's proposal, when it is an Allow / Deny menu (one call, the act model's rows), waits as a card, as an app's network ask does (`shellcore::deskask`). The kernel's terminal takes it (`TAKE_CARD`) when `desktop` shows and no other ask is up, and posts it on `desktop`'s trusted ask card. Code draws the call and the question, the person answers there, and an Allow mints the `ONCE` for the call as shown (ADR 0005 section 7). The panel and the window only put the question in line and never answer it, and neither does a typed "yes". No typed line at the trusted terminal asked for the card, so its highlight starts on Deny. At most four wait, and one older than a question's two minutes lapses ("expired" in the log). The panel shows what the answer came to, in code's words only: the run's result line or "Done.", a fixed line for Don't, a fixed reason for a failure. A card on the desktop now takes no key or click for `SETTLE_MS` (400 ms) after it shows, nor a key held since before it, so someone still typing their next line cannot answer it. And since no desktop card came from a line typed at the trusted terminal, `y` takes two steps: the first arms the card, which then says "y again", and a second fresh press runs it. A key repeat is not a second press. A click on Run runs it at once; `n` or Don't declines at once (the manager's review on #864). A call too long or not plain text for the card's menu is told so; it asks only in the console. A Rhai script the model wrote still asks a y/n question that only the console shows, because the card shows one call and never a script, so that line is refused with that reason. A follow-up is a card that shows a script whole.
