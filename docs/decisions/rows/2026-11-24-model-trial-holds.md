decision: A model trial holds through a second switch, a busy `llm`, a restart of `updated` and a failing LLM server; this amends the P4 rows on `modelchan` and on `updated` serving the model channel
---
**No switch while a boot judges a trial (#25).** `models use` (so `model_use` and its undo) is refused while a boot judges an attempted trial, as an import and a download are: "a model is on trial; ask again once it is kept or rolled back". An attempted trial is no longer replaced or cancelled (`trial::switch` gives `Switch::OnTrial`), and the verdict is written only over that trial's record as it stands (`trial::verdict`). Before, a switch then was overwritten by the old verdict, so the new model booted untried, or the acknowledged switch was lost.

**The way back is never guessed (#26).** A new trial's previous model is the one the next restart maps, as the record names it: a pending trial's way back (kept when the trial is replaced), a kept candidate, or the model a rollback put the hint back on, even while this boot still runs the candidate. Switching to a pending trial's way back cancels the trial: the hint goes back on it, and a `kept` record now names it, where before the record was deleted, so a later switch went back to whatever `llm` ran, possibly a rolled-back candidate. Only with no record is the way back the model `llm` runs, and when `llm` cannot say (no answer in time, or an app job's health that names no model) the switch is refused, "llm did not say which model it runs; ask again". Before, it recorded none, and a failed trial went back to no model. `models remove` holds to the same reading. The list shows as the next restart's model the one the hint is on, where it knows what runs. One case stays: with no record, a boot whose hint names a model the kernel could not map still records none as the way back, since only `fs` reads the hint.

**A restart of `updated` is not a hung boot (#27).** Every start of `updated` that judges a trial first points the hint at its way back, and a keep points it at the candidate again, so a boot after one that hung maps the way back whatever any start of `updated` got as far as. The first start of a boot marks a pending trial attempted that way, and rolls one already attempted back at once (K's rule). A start again within the boot (`restart=N`, N > 0: the supervisor now also counts a restart the user asked for, not against the cap or the backoff; its records are the kernel's, in memory, so N is 0 at every boot's first start) does not take N as proof that the first start got that far. It judges by what `llm` says this boot runs. An attempted trial is judged again: this boot's own candidate can be kept, and a hung boot's, whose mark moved the hint, finds the way back running and rolls back ("another model started in its place"). A pending trial is checked: if `llm` runs its candidate, loaded or not, this boot mapped it, and it is marked and judged; if another model or none, it was written this boot for the next restart, and it is left for that boot. A switch ends such a check. The writes and their order are `modelchan::trial`'s (`start`, `look`, `Switch::writes`), host-tested so that a cut after any write leaves no model the next boot maps without a trial.

**A failing server does not hide the local model (#28).** When `llm`'s server's health fails, `health` is still an error but ends with the status: the local one, cut to the 160-character error line with the model's words kept, or `remote` with no local model, so a switch or a remove goes on as before (`llmproto::health::reply`). The probation, a switch and a remove wait 6 s for `health` (`trial::HEALTH_WAIT_MS`), longer than `llm`'s 5 s wait on the server (`llmproto::health::SERVER_HEALTH_MS`); the list keeps 3 s, within the model manager's 5 s read. The probation leaves 5 s after each wait ends before the next, and a request that waited behind one takes its answer rather than wait again, so the shell's 10 s call holds it. `llm`'s no-model error now reads as no model (`health::state_of`), so such a trial rolls back at once ("no model started"), not after 300 s.

Host-tested in `modelchan`, `llmproto` and `supervise`; the `model-import`, `ui-models-use` and `app-models` boot cases run it under `full-ci`.
