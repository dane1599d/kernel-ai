needed-by: Agents, built 2026-11-11 (lane E; ADR 0013 section 2's "resumed exactly where it was"; host only; the model lane reviews `infer`)
decision: `Engine::continue_reply` carries an answer on from the last token it picked, so an agent preempted in the middle of a sentence resumes exactly; the scheduler's decode quantum is one `continue_reply` of one token
---
ADR 0013 promises that a background agent paused mid-sentence resumes "exactly where it was", and the scheduler (`agentsched`) plans decode quanta of one token. Nothing in `infer` could carry an answer on: `Engine::reply` is a whole call, and asking again with the partial answer as an assistant turn would be re-templated and re-tokenised. This adds `Engine::continue_reply(pending, max_new, sampler, on_step)` beside `reply` (no change to `reply`).

**What the state of an answer in progress is.** A reply that stops (`Next::Stop`) or ends at `max_new` returns before it runs the model on the token it just picked, so the slot's KV cache and cached tokens cover everything but that last token. The one thing the slot does not keep is the engine's `logits`, which the next token is picked from, and they are shared by every slot. So the whole resume state is the slot (KV and tokens, which a RAM snapshot or a spill file already restores), the last token picked (`pending`: the caller saw it as `Step::Token`), and the sampler, which holds the draw state of a seeded one. `continue_reply` runs the model on `pending`, which makes the logits again, then picks as `reply` does. A reply stopped during the prompt needs nothing new: asking for the same reply again reuses the cache.

**Tested on the fixture model, every tier, against the whole answer made in one go, token for token:** an answer stopped at the first, the middle and the last-but-one token and carried on; stopped and carried on one token at a time (the scheduler's quantum); another agent running a different prompt in another slot in between (so the engine's logits are not the agent's own); a RAM snapshot taken, another prompt taking the only slot, the snapshot restored, and the answer carried on; the same through a `kai-kv 1` spill file; a seeded sampler carrying its draws on; a reply stopped in its prompt and asked for again; and refusals (nothing to carry on, a token that does not exist) that leave the slot as it was. They are the guarantee the scheduler needs and S13-1 did not test (it restored a slot after the prompt and compared a follow-up reply, not an answer stopped half way).

**Not in this change:** answers under a grammar (the `act` and `script` paths) are not carried on, because the grammar's state is the reply's own; that is for the scheduler's first wiring to decide (those answers are short and the foreground's). `llm`'s use of any of it, and the per-token cost of one model step a quantum, wait for the scheduler after the v0.1 tag.
