needed-by: Agents, built 2026-11-11 (lane E; ADR 0013 section 3; found by the random-sequence tests of `kaimem`; host only)
decision: The memory store itself refuses what its file or its rules cannot hold: a memory for an agent named `all` (or for a scope that is no agent name), an edit into the text another memory of the scope already has, and a restore into a full store; random sequences of store calls are held to a model after every step
---
Three ways the store broke a rule it states, found by holding it to a model:

1. **A memory for an agent named `all` read back as everyone's.** `all` is the file's word for memories every agent sees (`scope=all`), and also a legal agent name (ADR 0011's shape, not one of the four built-in names). The store accepted `Scope::Agent("all")` from an agent named `all` writing its own, and `save` wrote `scope=all`, which `load` reads as `Scope::All`: after a reload that agent's private memory was in every agent's prompt and no agent could change it, a way for a package so named to put text in front of every other agent that the rule "an agent writes only its own" is meant to stop. A scope that is not an agent name (`Bad Name`, a newline, empty) was also accepted from the user and wrote a file that refused to load, and with it every memory in it. `remember` now refuses `Scope::Agent(name)` unless `name` has the agent-name shape and is not `all`; an agent named `all` keeps no memories of its own until the name is reserved (a follow-up for `kaiagent`'s `valid_id`, whose list of names no package may take is `kai`, `goals`, `index`, `maint` and which would add `all`).
2. **An edit made two of one.** `remember` of a text already kept for the scope gives the id it has, and `restore` keeps one of two (C on #650), but `edit` could change a memory into the text of another of the scope, so two said the same. `edit` now refuses it, naming the other (it is in a scope the editor sees, so it tells nothing); a memory may still change its own case.
3. **A restore past the limit.** `restore` pushed a forgotten memory back without looking at `MAX_MEMORIES`, so forgetting one, keeping another and restoring the first made 513. It now refuses when the store is full, and the memory stays forgotten, so it can be restored when there is room.

`kaimem/tests/props.rs` found them: a model of what is kept and what is forgotten sits beside the store, and 300 seeds of 250 random steps (remember with every kind of writer, scope and text, including duplicates by case and padding, texts a memory may not be, and 190 to 209 bytes against the 200 limit; edit; forget; forget all; restore; purge; the clock running on) are checked after every step: each reader's list, `get` and `search` are the model's (the user sees all, an agent its own and those for all), an agent probing an id it cannot see gets the same answer as for one that is not there, nothing is kept twice, ids are never handed out twice (a store loaded from its file hands out an id above every one made), `restorable` is the model's, and every ten steps the file the store wrote reads back as the same store and writes back byte for byte. The run counts the cases it reached and fails if any is rare. With the three fixes taken out, all four tests in the file fail; with them, they pass.
