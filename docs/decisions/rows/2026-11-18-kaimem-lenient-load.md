needed-by: Agents, built 2026-11-18 (lane AG; ADR 0013 section 3; host only, before the `memory` volume's wiring)
decision: A `kai-memory 1` file with a bad record loads every other memory and reports the bad one by its lines; a bad header or another version still refuses the whole file, and a memory's text may not start with `id=`
---
Before this, one bad record refused the whole file, and with it every memory the person kept: one stray byte from a torn write or a hand edit on the `memory` volume would have made Kai forget everything. Now `record::decode` finds records by their fields line, which starts with `id=`. A text never starts with `id=` (`text_problem` refuses it, so `remember` and `edit` do too), so the file finds its own records again after a bad one. Each record is its fields line and every line up to the next record. A record with no text, more than one line of text, fields out of shape, a text that cannot be a memory, an id an earlier record has, an id not below the header's next one, a text its scope already keeps, or a place past `MAX_MEMORIES` is skipped and reported as `Skipped { first, last, why }`. Lines before the first record are reported as stray. `Memories::load` returns the store and that report (`Loaded`, `#[must_use]`), and the wiring must tell the person, because a skipped record is gone at the next save. The header's next id is kept, so a skipped id is never handed out again. What loads keeps every rule the store keeps. The hostile test holds every mutated or cut file to that, and checks that each line after the header is in a record read or in one report. A new props test spoils one random record of a random store's file in six ways and checks that every other memory is read, with exactly that record reported.
