needed-by: the first-time-user audit, item 8 (the Editor loses unsaved text), built 2026-11-14 (AP-1; K or C reviews the comphost line)
decision: the Editor tells the host when its window holds text that is not saved, the app does not nap while it does, a close with such text asks Save, Discard or Cancel, and the file that was open opens again after a nap.
---
The founder typed in the Editor, went to the Terminal for two minutes and came back to an empty Editor: the app had napped, its checkpoint held nothing (`V1` had one reserved field), and the close button threw the text away without a word. Four changes. (1) The shared window loop gets the call that was already in `kai:ui/view@0.1.1`: `Sink::set_unsaved` (a default that says nothing, so no other app changes) and `Shown::mark_unsaved`, which sends the flag with the next present, before its commit, once per change, and again for a window opened anew. The Editor marks its window whenever `Files::unsaved` says so: edits the disk does not have, a component's source not built, or a line being typed. The flag reaches `desktop` as `toplevel.set_unsaved`, which is what makes the agent's `window_close` ask the user first (ADR 0005 section 6, until now never exercised by an app). (2) `comphost` holds the nap's lease while any of its windows' last frame says unsaved (`Ui::unsaved`, next to the lease it already holds for a change or a file in flight), so an Editor with unsaved text does not nap, whatever else is idle. A line of lane C's item 1 (typed input counts as use) is separate and is not touched here. (3) A close of that window does not close it: the status line says "Not saved" and a row of Save, Discard and Cancel buttons shows, with the keys S, D and Esc for the same (other keys are not typed meanwhile). Save sends Ctrl-S as typed, so the screen lets go of the line it holds, and closes when the file is written; a refused write keeps the window and says why in the status. Discard closes the window and drops the editor's state, so a window opened again says "No file is open". A component's source has nothing to save, so it has Discard and Cancel only. For this the window's `kai:ui/input` is bound in `editor-window` itself, with the Editor's own OS handle (it can write a file and draw the code view), and not with `comp-ui-bind`'s `input!`, which hands an app `kai:ui/view` alone; `EditorWindow::ui_event` replaces the `OnUi` impl. (4) The checkpoint keeps the path of the file open (`V1` gets an optional field 1, so a checkpoint the first version saved still imports and an older version reads a newer one), and a woken or swapped-in editor reads that file again from the disk, as for Ctrl-O. What is not kept: text not saved. A version swap, a restart or a crash with unsaved text loses it; the file comes back as the disk has it. Not covered by a boot case: the lease is a line in comphost with no host test (the loop is not testable off the guest), the rest is host-tested (`comp-ui-bind`, `comp-editor-ui` and `comp-editor-window`'s tests, including the three answers, the refused save and the old and new checkpoint). Lane C's `desk-nap-busy` case (the audit's test 3) is where the nap lease belongs under a boot, with a key sent to the Editor's window.
