needed-by: Agents, built 2026-11-11 (lane E; ADR 0013 section 5; found by the random-sequence tests of `goalcore`; host only)
decision: A goal that is stopped or gives up while a step runs counts that step as failed, as its log already says, so the goals file it is written to reads back; random sequences of goal calls are held to the approval's scope, budget and deadline after every step
---
`Goal::end` (cancel, fail) closes the step that was running by marking it `failed` in the log, but did not count it: `steps_run` and `failed` stayed as they were. `kai-goals 1` is read as hostile and its counts must be the log's (`steps_run == ran + failed`, `failed == the failed entries`), so a goal stopped while a step ran, a plain "stop it" on a running goal, wrote a file that the next read refused, and a refused file refuses every goal in it. `end` now counts the closed step as run and failed. The same step is not charged tokens (nothing says what it spent); the runner's later `finish_step` for it is answered `NoStepRunning` as before, so the `actlog` entry it made is not recorded in the goal and `undo goals` will not find it by that goal: a follow-up for the runner's wiring after the tag (it can record the entry before it reports).

`goalcore/tests/props.rs` found it, and holds the rest to what ADR 0013 section 5 says: goals are made (some with a scope or budget that `goal_set` must refuse), approved, resumed, raised, extended, forgotten and ticked, steps are proposed (half made to fit the approval, the rest with rows outside the scope, paths that leave a folder by `..`, `.`, a doubled or leading slash, a backslash, a look-alike folder name or a newline, and a door that asks for what has no undo or what content steers), answered by the person, finished, charged, stopped, and the clock runs on, over 300 seeds of 300 steps. After every step the goal's own record is held to the rules read again from their words, not from the code: a step that ran without a person's yes was a run-tier step inside the approved rows and folders, within every budget and the deadline, and, with the person away, in a goal that runs unattended; the kind of every ask is the first reason that applies (scope, then tier, then away); one step in flight, one record per step, the state agreeing with what the goal holds; at most `MAX_ACTIVE` live and `MAX_GOALS` kept, ids never reused; and every 25 steps the whole set reads back from its own text as the same goals. The run counts the cases it reached (steps that ran, that asked for each reason, held back, a goal ended mid-step, one forgotten) and fails if any is rare, so it cannot go quiet by not reaching them. Nothing else it checks was wrong.
