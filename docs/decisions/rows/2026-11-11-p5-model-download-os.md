---
**The chunk list.** The `models` role signs each model's `kai-chunks 1` list as `<sha256>.chunks`. The image's metadata holds that target, but its bundle does not carry the file: the name is past `kai-bundle 1`'s 64-byte path limit. So `updated` fetches it from the repository's targets, consistent-snapshot named (`targets/<list sha256>.<sha256>.chunks`) on the host that serves the metadata (`dane1599d.github.io`; the mock's `updates.kai.test`). It holds the list to the signed length and SHA-256, then to the model (`Job::check_list`), before any range of the model is asked for. The release workflow already uploads the committed lists (`models-chunks-<version>`). Publishing them at that path is task 18's, with the rest of the repository. The system plan's `NetDest` gains the Pages host.

**A chunk at a time.** `kainet::download::Download` (`start`, `step`) runs a download one step at a time. A step reads back and checks a chunk the checkpoint names, or fetches, checks, writes and records one, or checks the whole hash and moves the target in. `download()` is those steps in a loop, in the same order with the same errors, so its tests stand. The run holds one chunk-sized buffer where `download()` held two. `updated` steps once per tick of its serve loop, so the shell's and Models' requests are answered between 2 MiB chunks. A failed step leaves the run where it was, so the next try asks for that chunk again: after 1 s, doubling to at most 60 s, or as long as a 429 or 503 says, up to 8 tries in a row. A whole-file mismatch is final.

**Where the bytes wait.** `dlcheck`'s kaifs `Partial` (a chunk and its mark per action) moves into the user library as `user::kaifs`, unchanged. `updated` uses it in `.partial/` on the models volume (`<sha256>.partial` and `<sha256>.mark`). `fs` keeps only sealed blobs, so a model checked whole is not renamed. Once the disk holds a second copy (`disk_need`), it is copied into the store's sealed blob in one action, a chunk per tick, as an import is. Then the partial file is cut to nothing and trashed. An import, a switch and a download each wait while another changes the store.

**The case.** `model-download` (`test=update updated=download`): test images' role also signs `fixture-dl` (12 MiB), whose source is the mock's pinned resolve URL. That URL redirects to the storage host, which cuts the download at 40% and 80%. `updated` (`fetch=test`, a `NetDest` for the model, storage and repository hosts, `pages=6144`) prints its offers, the one ask, each try again, then the bytes, the time and MB/s. The store then lists the model. The guest has the memory xtask gives a VM for the model, and `kai-data` has 512 MiB. `model-import` now counts 6 signed models.
