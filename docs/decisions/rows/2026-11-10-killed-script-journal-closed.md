decision: A killed script child's journal is not moved back: reading the policy already sees every change a child can make
---
P1's close row left "moving a killed script's journal back from the child rather than reading the policy" for later. It is closed without that work. A script runs in the `scriptrun` child only when every call it makes is a row the child may run (`apart::may_run_apart`): no call-only row, no file row, no window row, no app row, and since #757 no network row. Of the rows a script may call (`agentabi::SCRIPT_CALLS`), the only one that changes anything outside the file rows is `set_policy`, and `apart::killed` already compares the policy and preset with the spec taken before the child's claim and logs the difference with its inverse, so `undo` puts it back. A journal sent back from the child would carry nothing more. The host test `set_policy_is_the_one_change_a_killed_child_can_leave` holds this: a new script row that changes state fails it, and must then give `killed` a way to see its change, or stay in the shell.
