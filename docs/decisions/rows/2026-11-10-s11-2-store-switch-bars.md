decision: S11-2's two timing bars hold under KVM for the 300 KiB `big`: an install took 0.21 to 0.41 s against the 3 s bar, and a rollback 9.5 and 14.6 ms against 100 ms.
---
ADR 0011's S11-2 passes only with an install of at most 3 s and a rollback of at most 100 ms under KVM, and neither had been measured. `pkg` now prints both against their bars for every install and undo of the `pkg-install` cases (the `pkgrepo=` mirror), `desk-catalog` (the same mirror, through the Apps sheet) and the `pkg-online` ones (over TLS): `pkg: install of big took N ms: within or OVER the 3000 ms bar` and `pkg: undo took N ms: within or OVER the 100 ms bar`. The line is a figure to read, not a check, since the cases also run under TCG, which no bar is for. One `full-ci` run (KVM, run 42742927717 on #768, shards 1 to 3) printed: **install of `big`** 322.6 ms (`pkg-install`), 326.7 ms (`pkg-install-rollback`), 210.1 ms (`desk-catalog`), 393.3 ms (`pkg-online`), 408.4 ms (`pkg-online-rollback`); **install again from the store after an undo** 59.5 ms and 36.8 ms (no fetch); **undo** 14.6 ms (`pkg-install` boot 2) and 9.5 ms (`pkg-online` boot 2). Every figure is within its bar, with more than ten times to spare on the rollback and about seven on the install. The caveat: `big` is the 300 KiB `data` package of two 192 KiB pieces, not S11-2's repository of a 900 KiB component, a 2 MiB `data` package of 40 files and a 64 KiB dependency (about 3 MiB). At the measured 1.1 ms a KiB that install would take about 3.3 s, over the bar, if time grew in proportion to size; a boot case with that repository would answer it, and none has been built.
