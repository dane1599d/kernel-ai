decision: An app's site word waits for a signed manifest that declares hosts, and Hold is deferred until the first send row
---
App site words. `Shell::add_app_hosts` and `remove_app_hosts` (`shellcore/src/sitewords.rs`) are built and tested, but nothing calls them yet: no signed manifest an app installs from declares hosts. kaipkg's header has no network field, app plan lines come from the system plan, and the only signed manifest with hosts is an agent package's `net` line (ADR 0013), which installs after the v0.1 tag. So for now an app's word grounds no host, and a fetch from an app's host asks unless the line names it. After the tag, agent-package installs call `add_app_hosts` with the manifest's `net` hosts and removals call `remove_app_hosts`, with a boot case for both. Widening kaipkg's package format for apps was not chosen: no app needs it yet.

Hold. Today it is only `Inverse::Hold { ms }` and its Ask tier in `agentabi`. A held send needs a queue in the shell, an expiry without threads (on the next line or the terminal's tick, so not exact to the millisecond), log states held, sent and cancelled, `undo` cancelling a held entry, a setting that is off by default, and a send row to hold. That is 600 to 800 lines, more than a day, and no row sends a message yet. P5's plan already lists "`Hold` for sends" under later work. So sends always ask in v0.2 (P5 question 5), and Hold is built with the first real send row (P8 accounts). No founder question is needed: this keeps the approved default.
