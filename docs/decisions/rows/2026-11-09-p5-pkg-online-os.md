decision: `pkg` installs from the online repository over TLS 1.3 on a `NetDest` of its own, on `user::tls`, built for the hard-float program class.
---
The OS half of P5 task 8, on the host half (`kaipkg::online`, #675) and the shared ring-3 client `user::tls` (#753, task 12's harness). `pkg` moves to the hard-float programs, where AES-NI and the vector paths run (plan section 4, item 3). `step=online*` runs the mirror cases' flow on `Online` instead of `Mirror`; the flow is now one function over a `Remote` and a `Source` (`install_from`), so the same checks run on what either fetches: metadata against the image's root, a package by length and hash, then its header. The plan line says which repository: `online=test` is xtask's HTTPS mock (`Hosts::mock`, equal to the mock's and the DNS zone's names by a host test), reached on port 443 through the harness and trusted through the bundle's `netroots/1.der`. `pkg`'s `NetDest` allows the mock's three hosts on 443 and nothing else, and a name off them is refused before a query leaves. Cases: `pkg-online` (install, undo, install again from the store) and ADR 0011's five tamper cases over the network, in `xtask/src/cases/online.rs`; a case sets `https` (T's `Https`) and `online` (the mirror kind the mock also serves, signed by the image's keys). Not here: the shipping system's repository (`Hosts::github`, port 443) waits for the follow-up that gives `pkg` an install request; `PKG_FETCH` with `pkgrepo=` stay until the `pkg-install` cases move to the mock. Cost: `pkg` now carries rustls and the crypto, so its loaded segments are 3.1 MiB instead of about 1, resident in every desktop boot; the first run of this task failed `desk-agent` and `desk-takeover` for it ("Not enough memory to open Notes").
