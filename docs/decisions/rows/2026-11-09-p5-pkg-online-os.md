The OS half of P5 task 8, on the host half (`kaipkg::online`, #675) and the shared ring-3 client `user::tls` (#753, task 12's harness). `pkg` moves to the hard-float programs, where AES-NI and the vector paths run (plan section 4, item 3). `step=online*` runs the mirror cases' flow on `Online` instead of `Mirror`; the flow is now one function over a `Remote` and a `Source` (`install_from`), so the same checks run on what either fetches: metadata against the image's root, a package by length and hash, then its header. The plan line says which repository: `online=test` is xtask's HTTPS mock (`Hosts::mock`, equal to the mock's and the DNS zone's names by a host test), reached on port 443 through the harness and trusted through the bundle's `netroots/1.der`. `pkg`'s `NetDest` allows the mock's three hosts on 443 and nothing else, and a name off them is refused before a query leaves. Cases: `pkg-online` (install, undo, install again from the store) and ADR 0011's five tamper cases over the network, in `xtask/src/cases/online.rs`. Not here: the shipping system's repository (`Hosts::github`, port 443) waits for the follow-up that gives `pkg` an install request; `PKG_FETCH` with `pkgrepo=` stay until the `pkg-install` cases move to the mock. TLS stays in the services, not in T's `fetch` (the manager, 2026-11-09): `fetch` is the apps' and the agent's interactive client (64 KiB bodies, 30 s, one call at a time), a 2 MiB-chunk download through it would need a redesign, and a TLS-linked service costs binary size, not privilege, since each holds only its own `NetDest`. The memory cost, measured on debug builds: `pkg`'s loaded segments went from 1.81 MiB (soft-float) to 3.20 MiB (hard-float with rustls and the crypto), +1.39 MiB, and the free memory of a default 512 MiB guest at boot went from 219 MiB (#753's run) to 217 MiB. Size-optimising the crypto crates only gets 3.20 to 2.87 MiB, since dependencies already build at opt-level 2. Two desktop cases failed on it ("Not enough memory to open Notes", the first `full-ci` run of this task): `desk-agent` and `desk-takeover` had under 2 MiB to spare, and their floors move from the default 512 to 520 MiB (`DESK_TLS_MIB`), which covers `pkg`'s growth and `updated`'s (+1.31 MiB, task 10) with room. Any other desktop case that fails the same way gets the same constant, and a row.
