needed-by: P5 task 8, built 2026-11-09 (AP-1; K reviews)
decision: `pkg` installs from the online repository over TLS 1.3 on a `NetDest` of its own, built for the hard-float program class, on a shared ring-3 client in `user::net`.
---
The OS half of P5 task 8, on the host half (`kaipkg::online`, #675). `user::net` is what every ring-3 TLS client uses (tasks 9, 10 and 12 too): a `Stream` over NET_CONNECT, SEND and RECV that waits with NET_POLL and never longer than 15 s, a `NetDial` that resolves a name on the process's own handle (RESOLVE_ON, so only names under its suffixes) and connects each address, `Entropy` for rustls from ENTROPY, and the TLS configuration for a set of roots on the wall clock the caller gives. `pkg` moves to the hard-float programs, where AES-NI and the vector paths run (plan section 4, item 3). `step=online*` runs the mirror cases' flow on `Online` instead of `Mirror`, so the same checks run on what it fetches: metadata against the image's root, a package by length and hash, then its header. The plan line says which repository: `online=test:PORT` is xtask's HTTPS mock, reached at 10.0.2.2 and trusted through one root certificate the case adds to the image's repository folder (`pkgrepo/tls-test-ca.der`); the handle allows the mock's three hosts on that port and nothing else, and a name off them is refused before a query leaves. Cases: `pkg-online` (install, undo, install again from the store) and ADR 0011's five tamper cases over the network. Not here: the shipping system's repository (`Hosts::github`, Mozilla's roots, port 443) waits for the follow-up that gives `pkg` an install request; and `PKG_FETCH` with `pkgrepo=` stay until the `pkg-install` cases are converted to the mock. `webpki-roots` (CDLA-Permissive-2.0, approved 2026-10-27) joins the user graph, so `about.toml` accepts that licence and `NOTICES.txt` is regenerated.
