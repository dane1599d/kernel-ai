If the mirror is taken, the download needs these before it can use GHCR or Docker Hub, beyond the spike itself:
- `kainet`: the OCI distribution flow. That is an anonymous bearer token from the registry's token endpoint, read from its JSON answer, and an `Authorization: Bearer` header on the registry's requests, never sent on to the host a blob redirects to. It also needs an `Accept` header for the manifest's media type, and the manifest read to find the model layer's digest. Today's request head carries only Host, User-Agent, Accept-Encoding, Connection and Range. URLs with a query, which a blob's signed redirect has, already parse.
- A blob GET, `/v2/<name>/blobs/sha256:<digest>`, redirects to a storage host with a URL that expires. `kainet::download` asks the source again for each chunk, so each chunk gets a fresh redirect.
- `modelchan::fetch`: a source form for a registry reference beside the Hugging Face resolve URL, a `Hosts` entry for the registry and its blob host (`ghcr.io` and `pkg-containers.githubusercontent.com` for GHCR), and those hosts in `updated`'s `NetDest` (`kabi::plan::UPDATED_NET`).
- The signed `models` role: the mirror's source beside each target's pinned URL. The chunk list does not change, since it is bound to the model's SHA-256.
