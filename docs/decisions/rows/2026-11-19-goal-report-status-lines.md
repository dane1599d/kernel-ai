decision: What `goals` reports for a queued command has one strict shape, written and read only by `goalcore::report`: `ok` alone or `ok` then one `goal <id> <state> <run>/<steps>` line per goal, `gone <id>` for a goal it does not have, or `err <why>`, which is never read for a status
---
The shell drops a goal's grant ceiling when a report says the goal ended, so before this any report line that began with a number and a final word did it, including a goal-list line that carried the goal's own words and the free text of an `err`. Now a status line holds four fields and no words: the goal's text never rides in a report, since the shell has it from `goal_set`. The state is goalcore's `State::word`, and each number has one spelling (digits, no sign, no leading zero). Statuses are read only under a first line that is exactly `ok`; an unknown goal has its own first word, `gone`, so nothing inside an `err` is ever matched, and `Report::encode` makes an `err`'s why one printable line of at most 200 bytes. `Report::parse` returns `None` for anything `encode` would not write, a goal listed twice and more than 16 lines included, and the shell then applies nothing. The shell drops a ceiling only on done, failed or cancelled, or on `gone` for the queued command's own goal; there is no `expired` word, and a goal past its deadline is `paused-deadline`, which is live. A-core and the manager agreed this shape on 2026-11-18. Tests cover every state, refusal of near-misses and of the old shape, and that damaging any byte of a good report is refused or reads back byte for byte.
