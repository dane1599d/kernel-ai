The founder decided on 2026-11-16 that a host grant made by the person's Allow on the trusted-path card also grounds the agent's `net_fetch` and `net_lookup` from that one host (ADR 0002 D3, amended in the same PR, says exactly what is checked). `shellcore::appgrants` reads `/system/state/netgrants` lazily: once per decision pass, and only when the rule reaches the grant check. A grant counts while `pkg` says its package is installed (`<x>-window` is package `<x>`), asked with a 2 s wait. The answer, or the lack of one, is kept for about 5 s and forgotten when Kai installs a package. Objects `any`, `none` and one-label names are skipped. A file out of shape, or a `pkg` with no clear answer, grounds nothing, and each such audit line is said once per reason. A this-session grant counts only once the boot has dropped last session's grants. Today a package leaves only by an undo of a local install. When `pkg` then says the package is gone, or cannot say, the undo drops the grants held under its name (and its `-window`) and audits them by package name. An undo of an upgrade keeps them, and a local install of a name `pkg` lacks drops any left under it. The package's current `NetDest` ceiling is not checked, because the shell has no trusted copy of it (the ceiling it sees comes from comphost with each ask). So a grant that a package update no longer names still grounds until it is revoked. That is a follow-up once `pkg` serves the signed manifest's `NetDest`. The app, not the person, chose the host, and the app controls text the model reads (its window title in the State line). The #961 security review showed that a path checked only word by word still carried data: unknown script text, `System`-steered loops, punctuation, case, order, repeats, pasted lines, and lines that asked for nothing online. A third re-review showed that word lists will never be complete, so that round closed the structural holes and stated the residual. `agentabi::consent_grant` runs a read whose host only a grant grounds only when five checks pass, in this order. (1) No sentence says to stay offline. "offline", "off line", "off grid", "disconnected", "unplugged" or "airplane mode" counts anywhere, and so does a word touching the network with any negation in the same sentence (a question's sentence runs on into its answer). The negations include `n't`, auxiliaries with `nt`, and the lists in ADR 0002 D3, with every apostrophe look-alike folded. A failure asks as `GrantOffline` before anything else, with no Always and no rule waiver. (2) The control and every argument are `Literal` with known text, and nothing `System` or `Content` was evaluated before the call, its own arguments and bare row calls included (the walk's `met` label). Otherwise it asks as `GrantSteered`. (3) The line asks to go online in plain words, or uses verbs only as verbs. Or the granting app's package name appears, but only on a line that asks to be told something, for a path with no digit, and when no part of the name is a common word. Otherwise it asks as `Ungrounded`. (4) The path is empty, `/`, or `/` plus one run of up to three of the line's words, in order, lower case, each once (`GrantPath`). (5) It is the only such read in the plan, and none is in a loop (`GrantMany`). The person's own Always rule for the host waives `GrantPath`, `GrantSteered` and `GrantMany`, as it waived the same calls' `Ungrounded` ask before this change. It never waives `GrantOffline`. Each ask says what decided it and never says "send". P-F is unchanged: a grant never names a destination for `Data`. Residual: a negation in words the lists do not know still lets a read run. It carries at most three of the line's own words, in order, with no digit when the app's name is the only signal, to a host of the app's grants. Whether the read happens, and its timing, is not a channel: anything System or Content evaluated earlier in the plan steers it. An app grant for UDP or another port grounds only the shell's HTTPS GET on 443. No model input changes: granted hosts are not listed in the prompt. So whether the real model uses a grant is not measured, and actbench and fluency, which decide with no grants, cannot see this change. Only grants made on main are affected, since the grant code never shipped in a release.
