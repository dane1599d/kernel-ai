The founder decided on 2026-11-16 that a host grant made by the person's Allow on the trusted-path card also grounds the agent's `net_fetch` and `net_lookup` from that one host (ADR 0002 D3, amended in the same PR, says exactly what is checked). `shellcore::appgrants` reads `/system/state/netgrants` lazily: once per decision pass, and only when the rule reaches the grant check. A grant counts while `pkg` says its package is installed (`<x>-window` is package `<x>`), asked with a 2 s wait. The answer, or the lack of one, is kept for about 5 s and forgotten when Kai installs a package. Objects `any`, `none` and one-label names are skipped. A file out of shape, or a `pkg` with no clear answer, grounds nothing, and each such audit line is said once per reason. A this-session grant counts only once the boot has dropped last session's grants. Today a package leaves only by an undo of a local install: that undo drops the grants held under the package's name (and its `-window`), and a local install of a name `pkg` does not have drops any left under it. The package's current `NetDest` ceiling is not checked, because the shell has no trusted copy of it (the ceiling it sees comes from comphost with each ask). So a grant that a package update no longer names still grounds until it is revoked. That is a follow-up once `pkg` serves the signed manifest's `NetDest`. The app, not the person, chose the host, and the app controls text the model reads (its window title in the State line). The #961 security review showed that a path checked only word by word still carried data: unknown script text, `System`-steered loops, punctuation, case, order, repeats, pasted lines, and lines that asked for nothing online. Two re-reviews then found more ways round. So `agentabi::consent_grant` runs a read whose host only a grant grounds only when five things hold. (1) The control and every argument are `Literal` with known text, and nothing `System` or `Content` was evaluated before the call (the walk's `met` label, which closes aborts, method mutation such as `push` and loop timing); otherwise it asks as `GrantSteered`. (2) The line has an un-negated plain-internet word or phrase, matched whole ("look up", never a bare "up"), or the granting app's package name when no part of it is a common English word; otherwise it asks as `Ungrounded`. (3) The line does not say to stay offline: "offline" or "off line" anywhere, or a word that touches the network in a line with any negation anywhere, curly apostrophes folded; otherwise it asks as `GrantOffline`, with no Always and no rule waiver. (4) The path is empty, `/`, or `/` plus one run of up to three of the line's words, in order, lower case, each once (`GrantPath`). (5) It is the only such read in the plan, and none is in a loop (`GrantMany`; the shell's plan lists a looped call twice). The person's own Always rule for the host waives `GrantPath`, `GrantSteered` and `GrantMany`, as it waived the same calls' `Ungrounded` ask before this change. Each ask says what decided it and never says "send". P-F is unchanged: a grant never names a destination for `Data`. Residual leak: which of an app's granted hosts a plan reads, and which run of up to three of the user's own words goes in its path (for a tagged call, which words the model picked). An app grant for UDP or another port grounds only the shell's HTTPS GET on 443. No model input changes: granted hosts are not listed in the prompt. So whether the real model uses a grant is not measured, and actbench and fluency, which decide with no grants, cannot see this change. Only grants made on main are affected, since the grant code never shipped in a release.
