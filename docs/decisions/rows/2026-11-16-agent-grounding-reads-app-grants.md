The founder decided on 2026-11-16 that a host grant made by the person's Allow on the trusted-path card also grounds the agent's `net_fetch` and `net_lookup` from that one host (ADR 0002 D3, amended in the same PR). `shellcore::appgrants` reads `/system/state/netgrants` lazily: once per decision pass, and only when the rule reaches the grant check. It counts a grant while `pkg` answers `actions <package>` for its app (`<x>-window` is package `<x>`). It skips `any`, `none` and one-label objects, and fails closed, with one audit line per new reason, on a file out of shape or a `pkg` that gives no clear answer. The package's current `NetDest` ceiling is not checked: the shell has no trusted copy of it (the ceiling it sees comes from comphost with each ask), so a grant a package update no longer names still grounds until it is revoked. That is a follow-up once `pkg` serves the signed manifest's `NetDest`. The app, not the person, chose the host, and the app controls text the model reads (its window title in the State line). So `agentabi::consent` lets a host grounded only by a grant run only when: no read content decided the call (`Why::GrantSteered`); no clause negates a net word or one of the row's cues (`Why::Ungrounded`); and every word of the path and query is a word of the line outside a negating clause (`Why::GrantPath`). Each of these asks with text that says what decided it and nothing about sending. P-F is unchanged: a grant never names a destination for `Data`. Residual risks: the model may write a granted host it saw in the State line with no path, which reveals only that a fetch happened, to a host the person already let that app reach; and an app grant for UDP or another port grounds only the shell's HTTPS GET on 443. No model input changes: granted hosts are not listed in the prompt, so whether the real model uses a grant is not measured, and actbench and fluency (which decide with no grants) cannot see this change either way. Only grants made on main are affected: the grant code never shipped in a release.
